NECROLOADER

Полное техническое задание

Версия: 1.1
Статус: Проектирование
Платформа: Xbox 360
Основная среда: Aurora + ABadAvatar + XeUnshackle 1.0.3
Язык: C++
Разработка: Windows 11 + OpenCode + AI Agents
Основная цель: автономный загрузчик игр и контента с дистанционным управлением через смартфон.

⸻

1. Концепция

NekroLoader — самостоятельное Homebrew-приложение для Xbox 360, предназначенное для поиска, получения, загрузки, проверки и установки игрового контента на внутренний HDD.

Главная особенность — возможность полностью управлять загрузками через браузер смартфона.

Xbox самостоятельно выполняет загрузку из интернета. Телефон используется исключительно как удалённый интерфейс управления.

Проект не должен зависеть от Omni360 или Archive.org.

Основные принципы

* Автономная работа на Xbox 360.
* Прямая загрузка через интернет.
* Несколько независимых источников.
* Поддержка HTTP/HTTPS.
* Возможность продолжения загрузки.
* Проверка целостности файлов.
* Поддержка торрент-файлов при наличии совместимого клиента.
* Установка контента на внутренний HDD.
* Интеграция с Aurora.
* Управление через геймпад.
* Полноценное дистанционное управление через смартфон.
* Отсутствие необходимости в ПК или сервере во время эксплуатации.

Использовать только законные источники и контент, на использование которого пользователь имеет права.

5. NekroLoader Remote

Приоритет: высокий.

Это одна из ключевых особенностей проекта.

NekroLoader должен самостоятельно запускать небольшой HTTP-сервер непосредственно на Xbox 360.

Сервер предоставляет доступ к веб-интерфейсу через локальную сеть.

Телефон и Xbox должны находиться в одной локальной сети.

Дополнительный сервер, компьютер или облачная инфраструктура не требуются.

5.1. QR-подключение

В главном меню Xbox должна присутствовать кнопка:

REMOTE CONTROL

После её выбора:

1. Проверяется доступность локальной сети.
2. Запускается встроенный HTTP-сервер.
3. Определяется локальный IP-адрес Xbox.
4. Генерируется временный токен подключения.
5. Создаётся QR-код.
6. QR-код отображается на экране телевизора.
7. Пользователь сканирует его камерой смартфона.
8. Открывается веб-интерфейс NekroLoader.

Пример адреса:

http://192.168.0.15:8080/remote?token=SESSION_TOKEN

Адрес и порт должны быть настраиваемыми.

QR-код должен содержать адрес подключения и временный токен авторизации.

Предусмотреть возможность:

* Обновить QR-код.
* Отключить удалённый доступ.
* Завершить активную сессию.
* Ограничить время действия токена.
* Просматривать состояние подключения.

5.2. Веб-интерфейс

Предпочтительно использовать HTML, CSS и минимальный JavaScript без тяжёлых фреймворков.

Все ресурсы интерфейса должны находиться локально на Xbox.

6. Добавление ссылок с телефона

Приоритет: критический.

Основная задача Remote — избавить пользователя от необходимости вводить длинные ссылки с геймпада.

6.1. Добавление прямой ссылки

На странице Add Download должно быть поле:

Paste download URL

Пользователь вставляет ссылку на файл.

Поддерживаемые типы:

* HTTP.
* HTTPS.
* Прямые ссылки на разрешённые файлы.
* Пользовательские зеркала.

После отправки Xbox самостоятельно получает файл из интернета.

Телефон не участвует в передаче самого файла.

6.2. Загрузка торрент-файла

Предусмотреть форму:

Upload .torrent file

Пользователь выбирает торрент-файл через стандартный файловый интерфейс iPhone.

Веб-сервер получает файл непосредственно от телефона и сохраняет его на HDD Xbox.

После этого Torrent Manager обрабатывает файл.

Важно: наличие загрузки .torrent не означает наличие BitTorrent-клиента. Необходимо отдельно реализовать или интегрировать совместимый клиент для Xbox 360.

6.3. Magnet-ссылки

Предусмотреть возможность вставки magnet-ссылок.

Поддержка активируется только после появления рабочего BitTorrent-модуля.

Если Torrent Manager недоступен, приложение должно сообщить об этом, а не создавать фиктивную загрузку.

6.4. Добавление XEX

Пользователь может вставить прямую ссылку на файл .xex.

После получения файла приложение должно:

1. Проверить размер.
2. Проверить контрольную сумму, если она известна.
3. Сохранить файл в выбранную папку.
4. Не запускать его автоматически.
5. Показать пользователю информацию о файле.

Необходимо предупреждать о рисках запуска неизвестных исполняемых файлов.

6.5. Добавление GOD

Поддержать прямые ссылки на GOD-пакеты.

После загрузки:

1. Проверить целостность.
2. Проверить структуру.
3. Определить допустимое место установки.
4. Предложить установить контент.
5. При подтверждении выполнить установку.

6.6. Добавление ISO

Поддержать прямые ссылки на ISO-образы.

Предусмотреть:

* Проверку размера.
* Проверку контрольной суммы.
* Сохранение временного файла.
* Возможность извлечения содержимого.
* Проверку свободного места.

7. Управление загрузками с телефона

Страница Downloads должна предоставлять:

* Название файла.
* Источник.
* Размер.
* Загруженный объём.
* Процент выполнения.
* Текущую скорость.
* Среднюю скорость.
* Оставшееся время.
* Состояние задания.

Доступные действия:

* Pause.
* Resume.
* Cancel.
* Retry.
* Remove.
* View Details.

Все действия должны синхронно отражаться на Xbox.

Изменение состояния через геймпад также должно отображаться на телефоне.

Для обновления информации использовать лёгкий механизм polling или WebSocket, если он окажется совместимым с целевой средой.

8. Безопасность Remote

Удалённый интерфейс должен быть доступен только внутри локальной сети.

Обязательные требования:

1. Случайный токен авторизации.
2. Ограниченный срок действия сессии.
3. Возможность отзыва токена.
4. Защита от CSRF.
5. Проверка всех входных данных.
6. Ограничение размера загружаемых файлов.
7. Запрет произвольного доступа к файловой системе.
8. Запрет автоматического исполнения полученных XEX.
9. Подтверждение установки через интерфейс.
10. Ограничение количества одновременных подключений.

Нельзя открывать Remote Server непосредственно в публичный интернет.

Необходимо предусмотреть отдельный режим только для чтения.

9. Download Manager

Основной модуль загрузок.

9.1. Функции

* HTTP/HTTPS.
* Пауза.
* Продолжение.
* Повторная попытка.
* Очередь.
* Сохранение состояния.
* Контроль скорости.
* Обработка сетевых ошибок.
* Автоматическое восстановление.

9.2. HTTP Range

Использовать HTTP Range для продолжения загрузок.

Перед продолжением проверять:

* Поддержку Range.
* ETag.
* Last-Modified.
* Размер файла.
* Совпадение идентификатора ресурса.

Не объединять части разных версий файла.

9.3. Зеркала

Если источник перестаёт отвечать:

1. Зафиксировать ошибку.
2. Проверить альтернативные зеркала.
3. Сравнить метаданные.
4. Проверить идентичность содержимого.
5. Продолжить загрузку только при подтверждённой совместимости.

Начальная версия должна поддерживать одну активную загрузку.

10. Torrent Manager

Отдельный модуль для BitTorrent.

Требования:

* Обработка .torrent.
* Обработка magnet.
* Получение метаданных.
* Поддержка HTTP и UDP tracker, если реализуемо.
* Peer discovery.
* Проверка частей.
* Возобновление загрузки.
* Ограничение скорости.
* Управление очередью.

BitTorrent необходимо рассматривать как отдельную техническую задачу.

Не начинать интеграцию до подтверждения возможностей сетевого стека Xbox 360.

В первую очередь использовать легальные раздачи homebrew и свободно распространяемого контента.

11. Source Manager

Единая система источников.

Каждый источник реализуется отдельным адаптером.

Типы источников:

* HTTP/HTTPS Mirror.
* Прямые ссылки.
* Пользовательские URL.
* Публичные каталоги разрешённого контента.
* BitTorrent.

Archive.org не должен быть обязательным источником.

Пользователь должен иметь возможность добавлять и удалять источники через телефон.

12. Installer

Поддерживаемые форматы:

* GOD.
* ISO.
* Extracted.
* XEX как отдельный исполняемый файл.

Функции:

* Проверка размера.
* Проверка целостности.
* Проверка свободного места.
* Выбор папки установки.
* Предупреждение перед заменой существующих файлов.
* Отмена операции, если это безопасно.
* Проверка результата.

Интеграция с Aurora должна осуществляться через поддерживаемые способы обновления игровой библиотеки.

Не изменять системные файлы Aurora без необходимости.

15. Проверка целостности

Основной алгоритм — SHA-256.

Дополнительно поддержать SHA-1 и MD5 для проверки старых метаданных.

Проверять:

* Размер файла.
* Контрольную сумму.
* Завершённость загрузки.
* Целостность отдельных торрент-частей, если используется BitTorrent.

Отсутствие опубликованной контрольной суммы не должно интерпретироваться как подтверждение безопасности.

20. Критерии готовности

Проект считается готовым только при выполнении следующих условий:

* XEX запускается в целевой конфигурации.
* Работает Ethernet.
* Работает прямое скачивание.
* Поддерживается докачка.
* Проверяется целостность.
* Очередь сохраняется.
* Remote Server работает непосредственно на Xbox.
* QR-код открывает интерфейс на iPhone.
* Ссылки добавляются с телефона.
* Телефон не передаёт скачиваемые игры через себя.
* Xbox самостоятельно скачивает файлы.
* Управление загрузками работает с телефона.
* Работает установка поддерживаемых форматов.
* Нет повреждения существующих файлов.

21. Ограничения и безопасность

* Не выполнять неизвестные XEX автоматически.
* Не открывать локальный сервер в публичный интернет.
* Не хранить пароли и токены в открытом виде.
* Не удалять пользовательские данные автоматически.
* Не форматировать HDD.
* Не выполнять неподтверждённые операции с системными разделами.
* Не использовать неподтверждённые SDK API.
* Не считать наличие торрент-файла доказательством наличия BitTorrent-клиента.

23. Финальная концепция

NekroLoader — самостоятельная система загрузки и установки контента для Xbox 360.

Xbox выполняет всю тяжёлую работу. Телефон предоставляет удобное управление.

Пользователь может:

1. Открыть NekroLoader на Xbox.
2. Нажать Remote Control.
3. Отсканировать QR-код.
4. Открыть страницу на телефоне.
5. Вставить ссылку или загрузить торрент-файл.
6. Добавить задание в очередь.
7. Следить за загрузкой с телефона.
8. Подтвердить установку.
9. Получить готовый контент в библиотеке.

Главный принцип:

Не заставлять пользователя печатать на геймпаде то, что он может сделать за несколько секунд на смартфоне.

NekroLoader должен быть самостоятельным, расширяемым и независимым от сторонних магазинов продуктом.
